Design system

A calendar people plan in, readable at a glance

The tokens, components and rules behind pastecal. Everything on this page is live: it loads tokens.css, style.css and nativecal/native.css and mounts the real components, so what you see is what ships.

Color is information

Categories are how groups plan. Events stay blocks of their color, never reduced to a dot.

Readable first

Text meets WCAG AA in both themes. Nothing under 11px, and 11px only for uppercase labels.

Familiar, then better

Layouts people know from today's calendar; cleaner type, spacing and surfaces on top.

One accent

Pink means "do this" and "today". Blue is only for links. Everything else is neutral.

Color

Neutrals carry the interface; the accent marks the one thing to do. Values are read live from tokens.css in each theme, and every text color is checked against the background it sits on.

Event colors

The sixteen default category colors (people can change them in Settings). All-day and multi-day events are solid bars whose text is black or white, whichever reads better on that color (NcUx.textOn); timed events are a tint of the color with a solid edge and dark text. White on orange was 2.2:1, which is why text color is chosen per color rather than fixed.

Typography

One family, the system UI font (San Francisco, Segoe UI, Roboto): crisp at small sizes, fast, familiar on every device. Hierarchy comes from size and weight, not from more fonts. Times use fixed-width digits so they line up down a column.

Icons

Lucide, 2px stroke, inlined in NcIcon.js (no font, no request). Use <nc-icon name="…">; never text glyphs like ▾ or ✕, which render differently on every platform. Add an icon by pasting its paths from lucide.dev.

Buttons

One filled button per surface: the thing to do. Everything else is quiet. Labels are verbs in sentence case ("Save", "More options"), never all caps.

Popups

Anchored to what was clicked, 12px corners, a popup-level shadow. The event popup is a plain card with a color square, so a light category color never puts white text on a pale header.

Event editor

Every field of an event in one dialog. The category dropdown names every label, because the labels are the information. Moving the start moves the end. On phones it becomes a bottom sheet.

Dialogs & Undo

Prefer Undo to "are you sure": the action happens at once and the snackbar offers a way back for 8 seconds. Ask first only when the question has real choices, like which events of a series.

Phone

The real calendar in a 390px frame (a view-only link, so nothing can be changed). Popups and the editor become bottom sheets over the calendar; event chips show titles; a tap anywhere in a day creates there. Touch targets are at least 44px.

Writing

Plain words from the user's side of the screen. Sentence case everywhere. Name things by what people recognize, not by how the code is built.
